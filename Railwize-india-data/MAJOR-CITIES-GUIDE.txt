RAILWIZE MAJOR-CITY CATALOGUE EXPANSION
======================================

Contents: 111 station records, 68 directional services (34 return pairs),
414 timetable stops, 3 seat classes per train, all 7 operating days.
Run ADD-MAJOR-CITY-ROUTES.sql. It works on its own or after LOAD-INDIA-CATALOGUE.sql.
Station codes are real; RW1001-RW1068 are Railwize-defined services.
Times and distances are internally consistent planning values, not Indian Railways'
official schedules or fares. No live railway feed is connected. Coordinates are
approximate station-area points for nearby search, not platform/navigation positions.
Train display names use natural city names with no test/demo labels.

IMPORT IN MYSQL WORKBENCH
1. Back up existing schemas. Start current train-service and schedule-service once
   with DDL_AUTO=update so the six catalogue tables exist; then stop app services.
2. Open ADD-MAJOR-CITY-ROUTES.sql on the same MySQL server holding
   railway_train_db and railway_schedule_db. Replace BOTH schema names throughout
   if yours differ. No new database is needed.
3. Execute the complete file in one connection, not one selected statement.
   Required privileges are listed at the start of the SQL. The user needs access
   to both schemas. Do not ignore an import error and assume it succeeded.
4. Look for MAJOR-CITY IMPORT SUCCEEDED, then inspect new/unchanged counts.
   Existing station rows are reused unchanged. An exact rerun inserts no duplicates.
   Changed/partial RW services cause a clear error and rollback. Nothing is deleted,
   and existing routes, bookings, seats and account data are never overwritten.
   Do not rerun to reset a train modified later by an administrator.
5. Restart services and frontend. Refresh the station suggestions/search page.
   Seat inventory is created by the existing booking workflow; do not insert seats,
   reservations or payments by hand. The loader does not reverse run cancellations.

WHY MUMBAI -> DELHI MAY HAVE SHOWN NO TRAINS
The original 12951 serves MMCT -> NDLS and has AC classes, not SL. Exact search
uses selected station codes, direction, published stops, selected class, source
operating weekday, future departure and cancellation state. A city is not one
interchangeable station: CSMT != MMCT, and NDLS != NZM != DLI != ANVT.
This expansion adds RW1001 MMCT -> NDLS and RW1003 CSMT -> NDLS with SL/3A/2A.
RW1003 also stops at NZM before NDLS. Return trains have different numbers.
If the SQL diagnostic returns a matching train but the website does not, verify
the service datasource/schema, loaded configuration, live train/schedule responses,
selected station codes, class and any dated cancellation. Do not insert duplicates
to hide a service/configuration failure. Old 12951 is not repaired or changed.

FARE / BERTH CHECK
SL: 2 coaches x 72 seats, base Rs40, Rs0.60/km, minimum Rs120 (S1/S2).
3A: 2 coaches x 72 berths, base Rs100, Rs1.50/km, minimum Rs300 (B1/B2).
2A: 1 coach x 48 berths, base Rs150, Rs2.20/km, minimum Rs450 (A1).
Fare=max(minimum,base + route distance x rate), multiplied by passenger count.
MMCT -> NDLS is 1,384 km: SL Rs870.40, 3A Rs2,176.00, 2A Rs3,194.80 per person.
Intermediate journeys use destination cumulative km minus boarding cumulative km.
PNR, WL promotion, PDF, calendar, emails, support and refunds use normal flows.
To check WL, use the existing smaller QA trains; do not shrink these published
capacities after bookings exist. Payments remain Razorpay test mode.

CONNECTION / NEARBY CHECKS
MAO -> TVC has no direct service in this expansion: look for MAO -> ERS -> TVC
with a compatible transfer window (up to 720 minutes); check the day-labelled
times below. These remain two independently booked legs.
YPR -> MAS with nearby enabled can use SBC/KJM. MS -> SBC can use MAS.
HYB -> MAS can use SC. SDAH -> GHY can use HWH. DLI -> MMCT can use NDLS.
Use a 25 km radius where available and include ground travel time yourself.
The alternate terminals YPR/MS/HYB/SDAH/DLI/ANVT/BDTS/SBT are included for nearby
lookup even when they have no new direct service of their own. Existing station
coordinates are preserved; the SQL lists missing/invalid ones for admin review.
Additional trains loaded previously can change which alternative ranks first.

DAY NUMBER RULE
Day 1 is departure day at the first station, not today's date. An intermediate
boarding date maps back to source run date using departure_day_number - 1.
Every source has NULL arrival; every terminal has NULL departure. Distances start
at 0 and strictly increase. Stops have consecutive sequence numbers. Every next
arrival follows the previous departure, including overnight and day-3 journeys.
